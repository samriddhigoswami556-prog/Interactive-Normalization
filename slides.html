The Challenge in RDBMS Design
Why manual normalization fails
  • •
    Combinatorial Explosion: Finding all candidate keys is an NP-hard problem; manual checks miss composite keys.
  • •
    Schema Anomalies: Un-normalized relations lead to severe insertion, update, and deletion anomalies.

    Lack of Diagnostic Feedback: Standard tools only output "3NF" without pinpointing which dependency failed or why.

Core Engine • Module 1

Module 1: Attribute Closure (X⁺) Calculation

Mathematical Algorithm
Fixed-point expansion on Armstrong's Axioms
  • 1.
    Init: Start with initial set: X⁺ = X.
  • 2.
    Iterate: For every FD Y → Z in F, check if Y ⊆ X⁺.
  • 3.
    Expand: If LHS is satisfied, union RHS: X⁺ = X⁺ ∪ Z.
  • 4.
    Stabilize: Repeat until no new attributes are added (fixed-point reached).

Core Engine • Module 2

Module 2: Candidate Key Discovery & Pruning

Search-Space Pruning Strategy
Eliminates naive 2ᴺ exponential brute-force
  • •
    Essential Attributes: Never appear on the RHS of any FD. MUST be present in every candidate key.
  • •
    RHS-Only Attributes: Appear only on the RHS. Can NEVER be part of any minimal candidate key.
  • •
    Middle Attributes: Appear on both sides; combinatorial subsets are tested in order of size.
  • •
    Minimality Guarantee: Discards any candidate superset that contains an already discovered key.
Classification & Output
Foundation for normal form analysis
  • ✔
    Prime Attributes: Attributes part of at least one candidate key (Emerald badge).
  • ✔
    Non-Prime Attributes: Attributes outside all candidate keys (Crimson badge).
  • ✔
    Derivation Accordion: Collapsible interactive log displaying subset tests and minimality checks.
Core Engine • Module 3

Module 3: Normal Form Diagnostic Engine

2NF Verification
Eliminates Partial Dependencies
  • •
    Condition: No non-prime attribute may depend on a proper subset of any candidate key.
  • •
    Diagnostic: Cites the specific key subset (e.g. A ⊂ {AB}) violating 2NF.
3NF Verification
Eliminates Transitive Dependencies
  • •
    Condition: For every non-trivial X → Y, either X is a Superkey OR Y is Prime.
  • •
    Diagnostic: Checks prime status of Y \ X to allow valid 3NF dependencies.
BCNF Verification
Strict Superkey Determinant
  • •
    Condition: For every non-trivial X → Y, X MUST be a Superkey.
  • •
    Diagnostic: Computes X⁺; flags BCNF failure if X⁺ ⊂ R.
